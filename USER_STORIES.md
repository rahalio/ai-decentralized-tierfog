# Tierfog — User stories

**Product:** [PRODUCT.md](./PRODUCT.md)


### IoT / edge platform engineer

- As an edge engineer, I want to attach a new RPL mesh domain to a site fog node via config, so that I am not ordering another custom gateway SKU.
- As an edge engineer, I want hierarchical tier maps, so that cascaded edges (vehicle as edge of city hub; devices as edge of vehicle) are explicit.
- As an FL engineer, I want round eligibility gated on network health, so that training rounds do not assume perfect connectivity.

### OT / site lead

- As a factory OT lead, I want in-place analytics on the shop-floor fog, so that we are not shipping 1,000,000 GB/day patterns upstream.
- As a hospital IoT lead, I want isolation between clinical video and low-power sensor meshes, so that one radio storm does not starve the other.
- As a site lead, I want quarantine of a compromised tier, so that the rest of the DAG continues.

### Security architect

- As a security architect, I want sphere-of-influence authentication before federated join, so that trust is not ambient.
- As a security architect, I want traceability of which tier produced an analytic artefact, so that accountability survives multi-hop meshes.
- As a security architect, I want federated addresses that never become a global cleartext PII directory, so that addressing stays safe.

### Capacity planner

- As a capacity planner, I want GB/day class forecasts by site type, so that fog sizing matches the deck’s deluge reality.
- As a capacity planner, I want backhaul-avoided metrics, so that in-place intelligence has a business case.

### Platform administrator

- As a platform admin, I want software gateway updates as protocols evolve, so that convergence does not freeze on 2018 radios.
- As a platform admin, I want tenant isolation on shared edge hosts, so that multi-tenant fog does not mix spheres.
